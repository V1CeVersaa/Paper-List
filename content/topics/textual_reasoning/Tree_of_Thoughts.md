## 1. Introduction

最开始，人们设计 LM 只是为了生成文本，但是现在的大语言模型已经展现出在数学、符号、常识以及知识推理等各种任务上的能力，但是其文本生成机制仍然是最初的自回归机制，在推理的时候线性生成 token，进行线性决策。因此对这样简单的机制是否支持大语言模型成为一个通用问题

人类认知相关的文献为我们回答这些问题提供了一些线索。关于“双系统（dual process）”模型的研究表明，人们在进行决策时会以两种模式参与其中：一种是快速、自动、无意识的模式（“系统 1”），另一种是缓慢、深思熟虑、有意识的模式（“系统 2”）[30, 31, 16, 15]。这两种模式此前已经被联系到多种机器学习中的数学模型。例如，人类和其他动物的强化学习研究就探讨过：在什么情况下会采用联想式的「无模型（model-free）」学习，又在什么情况下会采用更具计划性的「基于模型（model-based）」规划 [7]。语言模型在 token 级别上做出的这些简单联想式选择，也让人联想到“系统 1”；因此，它们可能会从一种更加深思熟虑的“系统 2”规划过程的增强中获益——这种规划过程可以：(1) 在当前决策中维护并探索多种不同的备选方案，而不仅仅是选一个；(2) 评估当前状态，并主动进行前瞻（lookahead）或回溯（backtracking），以做出更加全局性的决策。

为了设计这样一种规划过程，我们回到人工智能（以及认知科学）的起点，从 Newell、Shaw 和 Simon 自 20 世纪 50 年代以来探索的规划过程汲取灵感 [21, 22]。Newell 及其合作者把问题求解刻画为在一个组合型问题空间中的搜索，该空间可以表示成一棵树 [21]。因此，我们提出了用于通用问题求解的 Tree of Thoughts（ToT）框架。如图 1 所示，现有方法（后文会详细介绍）都是通过采样连续的语言序列来进行问题求解，而 ToT 会主动维护一棵「思维树」，其中每一个“思维（thought）”都是一个连贯的语言序列，作为问题求解过程中的一个中间步骤（见表 1）。这样的高层语义单元可以让语言模型通过一种同样以语言形式实例化的深思熟虑推理过程（图 2、4、6）来自我评估不同中间思维在向着问题解答推进方面的进展。这种通过语言模型自我评估和深思熟虑来实现搜索启发式的方法是新的——此前的搜索启发式要么是手工编程出来的，要么是通过学习得到的。

最后，我们将这种基于语言的“生成并评估多样思维”的能力，与搜索算法结合起来，比如广度优先搜索（BFS）或深度优先搜索（DFS）。这些算法允许在“思维树”上进行系统性的探索，并带有前瞻和回溯机制。

## 2. Background

使用 $p_\theta$ 表示一个带参数 $\theta$ 的预训练语言模型，用小写字母 $x, y, z, s, \dots$ 表示一个语言序列，比如 $x = (x[1], \dots, x[n])$，其中每个 $x[i]$ 是一个 token，因此
$$
p_\theta(x) = \prod_{i=1}^n p_\theta(x[i] \mid x[1\ldots i]).
$$

我们使用大写字母 $S, \dots$ 表示一组语言序列。过往的方法主要分为下面三种：

- Input-output (IO) Prompting：使用语言模型将问题输入 $x$ 映射为输出 $y$ 的最常见方式：$y \sim p_\theta (y \mid \text{prompt}_{\text{IO}}(x))$，其中 $\text{prompt}_{\text{IO}}(x)$ 会把输入 $x$ 包装上任务说明以及/或者少量的/Few-shot 输入–输出示例。为简单起见，我们记
    $$
    p_\theta^{\text{prompt}}(\text{output} \mid \text{input}) = p_\theta(\text{output} \mid \text{prompt}(\text{input}))
    $$

    这样 IO 提示可以形式化为 $y \sim p_\theta^{\text{IO}}(y \mid x)$。

- Chain-of-thought (CoT) Prompting：主要是为了解决那些输入 $x$ 到输出 $y$ 的映射并不直接的情况。主要想法是在输入 $x$ 和输出 $y$ 之间引入一条思维链 $z_1, \dots, z_n$，其中每个 $z_i$ 都是一个连贯的语言序列，作为问题求解过程中的有意义的中间步骤，比如在数学题中的一个中间等式。在使用 CoT 解决问题的时候，每一个思维都会被顺序采样 $z_i \sim p_\theta^{\text{CoT}}(z_i \mid x, z_{1 \dots i-1})$，然后最终综合思维链的所有中间过程输出 $y \sim p_\theta^{\text{CoT}}(y \mid x, z_{1 \dots n})$。在实践中，整段 $[z_{1 \dots n}, y]$ 会被看成一个连续的语言序列，在 $p_\theta^{\text{CoT}}(z_{1 \dots n}, y \mid x)$ 中一次性采样成一个连续的语言片段，对思维链的划分方式一般是隐含的，并没有显式标注。 

- Self-consistency with CoT (CoT-SC)：是一种集成方法，会采样 $k$ 条独立同分布的思维链 $[z^{(i)}_{1\dots n}, y^{(i)}] \sim p^{\text{CoT}}_\theta(z_1\dots z_n, y \mid x)$，然后返回一个最常被输出的结果 $\arg\max_y \#\{ i \mid y^{(i)} = y \}$。CoT-SC 比普通 CoT 做得更好，因为同一个问题通常会存在多种不同的思考过程，比如一个定理一般有多种证明方式，通过探索更丰富的思维链集合，最终输出的决策会更可靠。然而，在每一条思维链内部并没有对不同中间思维步骤进行局部探索，而且这种选择最频繁的启发式输出方式一般只在输出空间较小的时候才适用。

3 Tree of Thoughts：用语言模型进行深思熟虑的问题求解

“一个真正的问题求解过程，是反复利用已有信息发起探索，而探索又反过来披露更多信息，直到最终找到通往解答的道路。”——Newell 等人 [21]

关于人类如何进行问题求解的研究表明，人们会在一个组合型问题空间中进行搜索——可以把这个空间看成一棵树，树上的节点代表部分解，而边（分支）则对应于把这些部分解做出修改的各种操作 [21, 22]。应该沿着哪一条分支前进，是由某些启发式所决定的，这些启发式帮助我们在问题空间中导航，并引导问题求解者逼近最终的解答。

从这个视角来看，目前用语言模型来解决一般问题的方法存在两个关键缺陷：
	1.	局部层面：在同一条思维过程中，它们不会去探索不同的后续延续——也就是「这棵树的分支」；
	2.	全局层面：它们不会引入任何形式的规划、前瞻（lookahead）或回溯（backtracking），来帮助评估这些不同的备选方案——而这正是人类问题求解中典型的、带有启发式的搜索特征。

为了解决这些问题，我们提出了 Tree of Thoughts（ToT），一个允许语言模型在「思维」之上探索多条推理路径的范式（见图 1(c)）。ToT 将任何问题都表示为对一棵树的搜索：树中的每个节点是一个状态
s = [x, z_{1\cdots i}]
它表示一个部分解——由输入 x 以及到目前为止的思维序列 z_1, \dots, z_i 构成。

在具体实现 ToT 的过程中，需要回答四个问题：
	1.	如何把中间求解过程分解为一系列「思维步骤」；
	2.	如何在每个状态下生成潜在的下一步思维；
	3.	如何启发式地评估这些状态；
	4.	使用哪一种搜索算法。

⸻

1. 思维分解（Thought decomposition）

在 CoT 中，思维是连续采样出来的，但并没有显式做「一个 thought 到底是什么」的分解。而 ToT 会利用具体问题的结构，把中间求解步骤设计并划分成若干 thought。正如表 1 所示，根据不同问题的性质，一个 thought 可以是：
	•	几个词（Crosswords 任务中的一个单词），
	•	一行等式（Game of 24 中的一条中间算式），
	•	一整段「写作规划」（Creative Writing 中的一段写作计划）。

一般来说，一个 thought 应该满足两点：
	•	要足够「小」，这样模型才能在这个空间里生成有希望且多样的样本（比如直接让模型「生成整本书」通常太大了，很难连贯）；
	•	也要足够「大」，这样模型才能对它在解决问题上的前景做出评估（比如只生成一个 token 通常太小了，没法判断这个 token 是否朝着正确方向前进）。

（直觉：thought 就是“模型一次能有意义地评估”的最小语义单元。）

⸻

2. 思维生成器 G(p_\theta, s, k)

给定树中的一个状态
s = [x, z_{1\cdots i}],
我们考虑两种方式来为下一步思维生成 k 个候选：

(a) 通过 CoT prompt 独立同分布采样（Creative Writing，图 4）

对下一步思维
z_{i+1}^{(j)} \sim p^{\text{CoT}}_\theta(z_{i+1} \mid s)
= p^{\text{CoT}}_\theta(z_{i+1} \mid x, z_{1\cdots i}), \quad j = 1,\dots,k.

这种方式更适合 thought 空间很「丰富」的情形（例如每个 thought 是一整段文字），此时独立采样会带来足够的多样性。

(b) 用 “propose prompt” 依次提出候选（Game of 24，图 2；Crosswords，图 6）

[z^{(1)}, \dots, z^{(k)}] \sim
p^{\text{propose}}_\theta\bigl(z^{(1\cdots k)}_{i+1} \mid s\bigr).

这种方式更适合 thought 空间较为受限的情形（例如每个 thought 只是一个词、或者一行算式），在同一个上下文中「顺序提出不同备选」可以避免候选之间高度重复。

（换句话说：空间大 → 多次独立 sample；空间小 → 一次 prompt 里让模型列出若干备选。）

⸻

3. 状态评估器 V(p_\theta, S)

给定一批不同的候选状态（通常是一层 frontier）
S,
状态评估器要评估它们在朝向问题解答前进时的「进展程度」，从而为搜索算法提供启发式依据，用以决定保留哪些状态继续搜索，以及搜索的优先顺序。

在经典搜索算法中，启发式本来就是解决问题的标准手段，但往往是：
	•	要么由人手工编程（例如 DeepBlue [3] 的估值函数）；
	•	要么通过学习得到（例如 AlphaGo [29] 的 value / policy 网）。

这里我们提出第三种方式：让语言模型自己对状态进行深思熟虑的评估。在合适的场景下，这种深思熟虑型的启发式既可能比手工规则更灵活，也可能比学习得到的模型更省样本。

类似于思维生成器，我们也考虑两种评估策略：是独立地评估每个状态，还是把状态放在一起比较后投票。

⸻

(a) 对每个状态独立赋值（value each state independently）
对所有 s \in S，
V(p_\theta, S)(s) \sim p^{\text{value}}_\theta(v \mid s),
其中一个 value prompt 会围绕状态 s 进行推理，生成一个标量值 v（例如 1–10 分），或者一个类别（例如 sure / likely / impossible），再把这种类别启发式地映射成数值。

（这里的 value 本质上是对“从当前部分解继续，能否顺利解题”的主观打分。）

不同任务、不同 thought 阶段下，这种评估背后的推理方式可以有所不同。在本文中，我们探索了：
	•	用少量的向前「试算 lookahead」来评估（例如快速检查 5,5,14 是否可以通过 5+5+14 达到 24，或者“hot l” 是否可以补成 “hotel”）；
	•	加上一些常识判断（例如 1,2,3 这些数字太小，很难凑出 24；或者几乎没有单词会以 “tzxc” 起始）。

前者有助于提升 “好状态”，后者有利于剔除 “坏状态”。这些估值不需要非常精确，只要在决策时“差不多够用”即可。

⸻

(b) 在状态之间投票（vote across states）
在这种策略下，
V(p_\theta, S)(s) = \mathbf{1}[s = s^\*],
其中「好状态」
s^\* \sim p^{\text{vote}}_\theta(s^\* \mid S)
是通过一个 vote prompt，在对集合 S 中不同状态进行深思熟虑的比较之后投出来的。

当问题的成功与否不容易被直接赋值（例如文章段落之间的整体连贯性），更自然的做法就是在多个部分解之间进行比较，然后投票选出最有前景的那个。

这在精神上类似于一种「逐步的 self-consistency 策略」：把“应该扩展哪个状态”看作一个多选题（multi-choice QA），再用语言模型的样本对这个多选题进行投票。

对于上述两种策略，我们都可以多次调用语言模型来聚合多个 value / vote 的结果，从而用更多的时间 / 资源 / 成本换取更加可靠的启发式。

（直觉：方案 (a) 是“逐个打分”，方案 (b) 是“放在一起比较、选最优”。）

⸻

4. 搜索算法（Search algorithm）

最后，在 ToT 框架下，可以根据当前「思维树」的形状来选择不同的搜索算法进行「即插即用」。在本文中，我们探索了两种相对简单的算法，并把更高级的算法（如 A* [11]、MCTS [2]）留给未来工作：

(a) 广度优先搜索（BFS，算法 1）

BFS 在每一步维护一个包含 b 个最有前景状态的集合。我们在 Game of 24 和 Creative Writing 这两个任务中使用 BFS，因为：
	•	它们的树深度有限（T \le 3），
	•	并且一开始的几个思维步骤就可以被评估，从而剪枝为一个较小的集合（b \le 5）。

(b) 深度优先搜索（DFS，算法 2）

DFS 每次优先探索最有前景的状态，直到：
	•	要么达到最终输出（t > T），
	•	要么状态评估器认为从当前 s 出发不可能解决问题（对单一状态的评估 V(p_\theta,\{s\})(s) \le v_{\text{th}}，其中 v_{\text{th}} 是一个阈值）。

在第二种情况中，从 s 出发的整棵子树会被剪枝，以便在「探索」与「利用」之间做出权衡。无论哪种情况，DFS 之后都会回溯到 s 的父状态，继续探索其他分支。

ToT 作为通用问题求解方法的几个概念性好处

从概念上看，ToT 在用语言模型做通用问题求解时有几个优势：
	1.	通用性（Generality）
IO、CoT、CoT-SC 以及 self-refinement 都可以被视为 ToT 的特殊情形（即树的深度与宽度被限制住的情况，见图 1）。
	2.	模块化（Modularity）
底层的语言模型、思维分解方式、生成方式、评估方式以及搜索过程都可以彼此独立地替换、组合。
	3.	适应性（Adaptability）
可以根据不同问题的性质、语言模型的能力、以及资源约束做出调整——例如在推理性能和计算成本之间做 trade-off。
	4.	方便性（Convenience）
不需要额外训练，只要有一个预训练语言模型就可以使用 ToT。
